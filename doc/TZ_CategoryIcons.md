# ТЗ: Line-іконки категорій замість emoji

Статус: відкрито. Місце розміщення: `apps/web/src/app/[locale]/page.tsx`,
масив `categories` (`🔆`/`🔋`/`⚡`), і потенційно `Header.tsx`/фільтри
каталогу, якщо рішення визнають вдалим після застосування на головній.

## 1. Контекст і причина

Три картки категорій на головній сторінці зараз використовують emoji
(`🔆` сонячні панелі, `🔋` акумулятори, `⚡` контролери) замість
іконок. Для магазину з середнім чеком $700–3500+ emoji зчитуються як
"чернетка"/недороблений дизайн, не як завершений продукт — рендер emoji
до того ж відрізняється між ОС (Windows/macOS/Android можуть показувати
той самий символ по-різному), тобто це ще й нестабільність вигляду, не
тільки естетика.

## 2. Стиль іконок

- **Тип**: line-іконки (контурні, не заповнені/glyph) — узгоджується з
  загальним спокійним, не кричущим стилем сайту (кольори `leaf`/`sun` з
  Tailwind-конфігурації, м'які заокруглені картки)
- **Товщина лінії**: 1.5–2px при базовому розмірі 24×24 (стандарт для
  сімейств на кшталт Lucide/Feather/Heroicons outline)
- **Заокруглення кутів**: `stroke-linecap="round"`, `stroke-linejoin="round"`
  — м'якіше, відповідає заокругленим карткам (`rounded-2xl`) на сторінці
- **Колір**: `currentColor` (успадковує колір тексту з батьківського
  елемента, не хардкоджений hex) — дозволяє перефарбовувати іконку через
  Tailwind-класи (`text-leaf-900` за замовчуванням, можна `text-sun-500`
  для hover-стану)
- **Формат файлу**: SVG (inline React-компоненти, не PNG/іконочні
  шрифти) — той самий підхід, що вже використовується для схем
  калькулятора (`SchemaDiagram.tsx`) і `CycleMap` з лендінгу Devil's
  Advocate (пам'ятка з історії проєктів)

## 3. Три конкретні іконки

### 3.1 Сонячні панелі (заміна `🔆`)
Прямокутна панель з характерною сіткою квадратних комірок (типово
3×2 або 4×3 клітинки всередині прямокутної рамки) — найбільш пізнаваний
силует для "сонячна панель" у порівнянні з абстрактним сонцем (сонце вже
асоціюється з погодою/освітленням, не з продуктом).

### 3.2 Акумулятори (заміна `🔋`)
Класичний силует батареї (прямокутник з невеликим "плюсовим контактом"
зверху) — не смартфонна іконка рівня заряду (яка асоціюється з UI
телефону, не з фізичним продуктом).

### 3.3 Контролери заряду (заміна `⚡`)
Найскладніший випадок — немає настільки ж усталеного піктограмного
стандарту, як для панелей/батарей. Рекомендований підхід: невеликий
прямокутний корпус пристрою (як плата/блок) зі стрілкою або блискавкою
всередину нього (не окрема блискавка сама по собі — щоб відрізнялося від
загальної "електрики"/"швидкості", які теж часто позначають блискавкою).
Альтернатива — мікросхема/плата з контактами по краях.

## 4. Технічна реалізація

```tsx
// apps/web/src/components/icons/SolarPanelIcon.tsx (приклад структури)
export function SolarPanelIcon({ className }: { className?: string }) {
  return (
    <svg viewBox="0 0 24 24" fill="none" stroke="currentColor" strokeWidth={1.5}
      strokeLinecap="round" strokeLinejoin="round" className={className}>
      {/* конкретні path — домальовуються при виконанні */}
    </svg>
  );
}
```

- Три компоненти: `SolarPanelIcon.tsx`, `BatteryIcon.tsx`,
  `ControllerIcon.tsx` у новій директорії `apps/web/src/components/icons/`
- У `page.tsx` масив `categories` замінює поле `emoji: string` на
  `Icon: React.ComponentType<{ className?: string }>`, рендериться як
  `<cat.Icon className="h-10 w-10 text-leaf-900" />` замість
  `<span className="text-4xl">{cat.emoji}</span>`
- Розмір у картці — 40×40px (`h-10 w-10`), трохи більший за типовий
  UI-розмір іконки (24px), бо тут це не допоміжний елемент інтерфейсу, а
  основний візуальний акцент картки

## 5. Джерело іконок — два варіанти

1. **Готовий набір** (швидше) — Lucide/Heroicons/Feather мають "battery"
   і загальні "grid"/"panel"-подібні іконки, які можна взяти як
   відправну точку й підправити; жодна з популярних бібліотек не має
   готової іконки саме "сонячна панель" з сіткою комірок чи "контролер
   заряду" — ці дві доведеться домалювати вручну навіть при цьому підході
2. **Намальовано з нуля** — повний контроль над виглядом усіх трьох,
   гарантована візуальна консистентність між собою (той самий stroke-width,
   той самий "характер" ліній) — довше, але для рівно трьох іконок
   різниця в часі невелика

## 6. Критерії готовності

- [ ] Три SVG-компоненти в `apps/web/src/components/icons/`, кожен
      приймає `className` і використовує `currentColor`
- [ ] Emoji в масиві `categories` на головній сторінці замінені на
      компоненти-іконки
- [ ] Іконки візуально консистентні одна з одною (однакова товщина лінії,
      однаковий стиль заокруглень) при перегляді трьох карток поруч
- [ ] Перевірено, що іконки коректно перефарбовуються при зміні
      Tailwind-класу кольору тексту (`currentColor` дійсно працює)
